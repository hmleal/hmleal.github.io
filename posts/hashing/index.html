Hashing passwords

Have you ever wondered how websites actually store your passwords? How do they know what you typed is actually correct and let you access your data?

Hashing

The magic behind this is the work hashing, imagine a function that accepts the password as a parameter and it generate “random” sequence of caracthers so the developers of the website cannot look at it and identify your password.

import hashlib


def encode(password):
    password_hash = hashlib.md5(password.encode("UTF-8")).digest()
    return "%s$%s" % ("md5_custom", password_hash.hex())


for password in (encode("2244"), encode("4466")):
    print(password)

This is basically what Django does with your password before storing, Django only store a hash that can be checked when you try to login again in the future. Since the beginning of internet different hash methods have been used, include MD5.

Rainbow table

The problem with this system is that passwords can be calculated and stored into a rainbow table a pre-calculated table with a list of passwords - In fact all common passwords could be stored and in case a hacker get access to the database what he needs to know is to check the passwords agains the rainbow-table and he can have access to your account.
